# 09 — Подвійний маятник: що перенесеться

## Чому обраний підхід — правильний і для подвійного

Є два популярні способи підняти маятник:

| Підхід | Одинарний | Подвійний |
|---|---|---|
| **Керування енергією** (Åström–Furuta): качати, доки енергія не дорівнюватиме енергії верхнього стану | працює | **не працює**: одне число енергії не визначає, як розташовані *дві* ланки — енергія може бути правильна, а ланки складені не так |
| **Траєкторія + слідкувальний регулятор** (наш) | працює | стандартний метод (напр. Graichen et al., 2007) |

Тому все, що зроблено для одинарного, — це вже «половина» подвійного.

## Що лишається без змін

- Архітектура: одне C-ядро для прошивки і симуляції.
- Кінематичний візок: вхід — прискорення візка.
- Безпека, хомінг, позиція з лічильника кроків, стопери, телеметрія.
- Пайплайн: CasADi-оптимізація → TVLQR → C-заголовок.
- Пайплайн SysID: тріали → фіт → перевірка → генерація.

## Що треба змінити

| Частина | Зміна |
|---|---|
| Модель | 6 станів: x, θ₁, θ₂, v, ω₁, ω₂. Рівняння Лагранжа для двох ланок з прискоренням візка на вході |
| Генератор траєкторії | та сама програма CasADi, нова модель; K(t) — 6 коефіцієнтів замість 4 |
| `controller.c` | вектор стану довільної довжини, оцінювач для двох кутів, LQR на 6+1 станів, гасіння двох мод коливань |
| Залізо | **другий енкодер у шарнірі між ланками**. Дроти — через слип-кільце або бездротово; він додає масу першій ланці |
| SysID | більше параметрів: дві ланки + зв'язок між ними |

## Ризики

- **Точність моделі.** Подвійний маятник хаотичний: підйом потребуватиме
  похибки моделі ~1–2% (зараз для одинарного вистачає −8…+12%).
- **Рейка й двигун.** Подвійному зазвичай потрібно більше ходу й прискорення.
  Це можна перевірити **до того, як будувати залізо**: прогнати оптимізатор з
  планованими довжинами й масами ланок і подивитися, чи існує розв'язок у
  межах ±35 см і можливостей двигуна.
- **Частота кроків TB6560** (~15 кГц) може стати обмеженням.

## Можливий порядок робіт

1. Вибрати довжини/маси ланок → перевірити здійсненність підйому оптимізатором.
2. Узагальнити ядро на N ланок (одинарний стане частковим випадком і має
   пройти той самий автотест).
3. Модель подвійного в `plant_sim.c` → баланс подвійного в симуляції.
4. Залізо: другий енкодер → SysID → баланс на стенді → підйом.
