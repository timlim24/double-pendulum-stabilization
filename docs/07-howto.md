# 07 — Як запускати

Усі команди — з кореня проєкту. Порт `/dev/ttyUSB0`; якщо інший — замініть.

## Один раз

```bash
./venv/bin/python -m pip install -r requirements.txt   # саме так: pip у venv зламаний (venv переносили з теки ПОК/)
. ~/.espressif/v6.1/esp-idf/export.sh                   # у кожному новому терміналі
```

## Повний цикл зі стендом

```bash
# 0. (за бажанням) перевірка в симуляції
./venv/bin/python single_pendulum/selftest.py

# 1. Калібрування кроку — після зміни рейки/шківа/мікрокроку
idf.py -C esp32_step_calibration -p /dev/ttyUSB0 build flash monitor   # вихід: Ctrl+]
#    → вписати STEPS_PER_METER у common/cart_pole_config.h

# 2. Основна прошивка (маятник при ввімкненні висить спокійно!)
idf.py -C esp32_cart_pole -p /dev/ttyUSB0 build flash

# 3. SysID — після зміни механіки
./venv/bin/python sys_id.py --port /dev/ttyUSB0 --flash

# 4. Робота
./venv/bin/python cli_control.py --port /dev/ttyUSB0
```

Порт може тримати лише одна програма — закривайте монітор/CLI перед наступною
командою. Немає прав на порт: `sudo usermod -aG dialout $USER` і перелогінитись.

## Клавіші `cli_control.py`

| Клавіша | Дія |
|---|---|
| S | підйом (у стані `ОЧІКУЄ 's'`) |
| X / пробіл | стоп |
| H | хомінг |
| C | поточне місце = центр (якщо стопери недоступні) |
| I | SysID (краще через `sys_id.py`) |
| Q | вихід |

## Телеметрія (10 разів на секунду)

```
[БАЛАНС] X:+0.002m | V:+0.01m/s | L:1 R:1 | Кут: +0.1° (вниз:+180.0°) | w:+0.02 | Тіки:12345 Нуль:11145 | Кроки:105/105 | home OK | цикл:85мкс
```

| Поле | Що означає |
|---|---|
| `[...]` | поточний стан, див. [04](04-control.md#автомат-станів) |
| `X`, `V` | положення (м) і швидкість (м/с) візка |
| `L`, `R` | стопери: 1 = вільно, 0 = натиснуто |
| `Кут` / `вниз` | кут від верху / від низу (°) |
| `w` | кутова швидкість (рад/с) |
| `Тіки`, `Нуль` | сирий лічильник енкодера і тік, що відповідає «низу» |
| `Кроки:A/B` | A — кроки за апаратним лічильником, B — розрахункові. Мають бути майже рівні. `(!PCNT)` — лічильник не працює |
| `home OK` | X відкалібрований по стоперу |
| `цикл` | найдовший час обчислення такту, мкс (має бути ≪ 2000) |

## Події (рядки `EVT:`)

| Подія | Коли |
|---|---|
| Стопер знайдено: X=−0.3995 м | хомінг успішний |
| Маятник спокійний внизу | готовий до `S` |
| СТАРТ ПІДЙОМУ | |
| ВЕРХ ЗЛОВЛЕНО: БАЛАНС | |
| Маятник упав / Програмна межа рейки | вихід з балансу |
| Підйом скасовано: X за межею / відхилення від траєкторії | підйом не вдався |
| Контакт зі стопером ... корекція X N мм | візок уперся; N — наскільки X «з'їхав» (пропуски кроків?) |
| Нуль енкодера скориговано на N° | нуль виправлено автоматично |
| Команду відхилено | команда не підходить до поточного стану |

## Що змінити, якщо...

| Хочу | Де | Потім |
|---|---|---|
| Інші межі рейки, швидкості, пороги | `common/cart_pole_config.h` | `selftest.py`, прошити |
| Агресивніший/м'якший баланс | `lqr_q`, `lqr_r` у `common/pendulum_params.json` | `python single_pendulum/params.py`, прошити |
| Інший підйом (ліміти, час) | `T_TOTAL`, `X_MAX`, `V_MAX`, `A_MAX` у `single_pendulum/mpc_generator.py` | `python single_pendulum/mpc_generator.py`, `selftest.py`, прошити |
| Новий маятник | — | `sys_id.py --flash` |
| Нова рейка | `RAIL_BETWEEN_STOPPERS_M` | калібрування кроку, прошити |

`pendulum_params.h` і `swingup_trajectory.h` руками **не редагуються** — вони генеруються.

## Якщо щось не так

| Симптом | Що перевірити |
|---|---|
| Після ввімкнення не їде до стопера | `L:`/`R:` у телеметрії (стопер «натиснутий» постійно?), живлення драйвера |
| `Кроки:A/B` дуже різні або `(!PCNT)` | перевірити, що ESP32 бачить пін 18 як вхід; позиція тоді рахується з команд (як раніше) |
| Великі «корекція X» при контакті зі стопером | губляться кроки: струм драйвера, мікрокрок, частота > 15 кГц |
| Довго не переходить в `ОЧІКУЄ 's'` | маятник не заспокоюється: тертя/люфт; нуль виправиться сам за ~1 с спокою |
| Підйом скасовується «відхилення від траєкторії» | модель застаріла → `sys_id.py --flash` |
| Підйом скасовується «X за межею» | те саме, або пропуски кроків |
| Баланс тремтить, вал «дриґається» | нормально в малих межах (квантування енкодера); великий люфт паса — підтягнути |
| `sys_id.py`: «Якість фіту низька» | подивитись `sysid_result.png`, див. [05](05-sysid.md#як-читати-графік-якщо-щось-не-так) |
