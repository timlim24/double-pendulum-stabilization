# 10 — Словник

| Термін | Пояснення |
|---|---|
| **Cart-pole** | «Візок з маятником» — класична задача теорії керування |
| **Нестійка рівновага** | стан, з якого найменше відхилення росте (маятник угорі). У нас відхилення подвоюється за 0.12 с |
| **Стан системи** | мінімальний набір чисел, що повністю описує систему зараз: x, θ, v, ω |
| **Зворотний зв'язок** | керування за вимірами: подивились, як відхилились → виправили |
| **Прямий зв'язок (feedforward)** | керування за планом, без вимірів (програвання траєкторії) |
| **LQR** | Linear-Quadratic Regulator. Лінійний регулятор `a = −K·s`; K обчислюється з моделі так, щоб мінімізувати «штраф за відхилення + штраф за зусилля». Q, R — ваги цих штрафів |
| **Рівняння Ріккаті** | матричне рівняння, розв'язок якого дає K для LQR |
| **TVLQR** | Time-Varying LQR: LQR, у якого K змінюється в часі вздовж заданої траєкторії. Тримає систему на плані |
| **MPC** | Model Predictive Control: щотакту розв'язувати оптимізацію на кілька секунд уперед. У нас оптимізація робиться **один раз заздалегідь** (траєкторія + TVLQR) — це дешевше і працює на ESP32 |
| **Пряма колокація** | спосіб оптимізації траєкторії: невідомі — стан у кожній точці часу, а рівняння руху — обмеження між сусідніми точками |
| **CasADi / IPOPT** | бібліотека для таких задач оптимізації / розв'язувач нелінійних задач, який вона викликає |
| **SysID** | System Identification — вимірювання параметрів моделі за записом реального руху |
| **Фіт** | підбір параметрів, щоб модель збіглася з даними |
| **Крос-валідація** | перевірка на даних, які не брали участі у фіті (у нас — тріал 3) |
| **СКВ / RMS** | середньоквадратичне відхилення — «типова похибка» |
| **R²** | частка поведінки, яку пояснює модель (100% = ідеально) |
| **ω0** | власна кутова частота маятника, 5.87 рад/с (період 1.07 с) |
| **γ, κ** | чутливість маятника до прискорення візка; κ — поправка «реальний рух / команда» |
| **Оцінювач (observer)** | алгоритм, що з шумних вимірів відновлює стан, якого не міряють напряму (тут ω) |
| **Альфа-бета фільтр** | найпростіший оцінювач «положення + швидкість» з двома коефіцієнтами корекції |
| **Немінімально-фазова система** | щоб рушити в один бік, спершу треба рухнути в інший (візок під маятником) |
| **Цифровий двійник** | симуляція, що виконує той самий код керування, що й реальний пристрій |
| **Кроковий двигун** | обертається дискретними кроками на кожен імпульс; позиція визначається кількістю імпульсів |
| **Мікрокрок** | драйвер ділить фізичний крок двигуна (1.8°) на 2, 4, 8, 16 частин — плавніше, але більше імпульсів |
| **Пропуск кроків** | двигун не встиг за імпульсами (замале зусилля/завелика частота/різке прискорення) — позиція «з'їжджає» |
| **Люфт** | зазор у передачі: вал повертається, а візок ще стоїть |
| **STEP / DIR / EN** | сигнали драйвера: імпульс кроку / напрямок / увімкнення |
| **Енкодер, PPR, CPR** | датчик кута; імпульсів на оберт (600); відліків на оберт з квадратурою (2400) |
| **Квадратура** | два зсунуті сигнали A/B — дають і напрямок, і ×4 роздільність |
| **Кінцевик (стопер)** | вимикач на кінці рейки |
| **Дебаунс** | ігнорувати короткі «брязкоти»/завади: стан змінюється, лише якщо сигнал стабільний кілька вибірок |
| **Хомінг** | пошук точки відліку (стопера) після ввімкнення |
| **LEDC** | блок ESP32 для генерації ШІМ — у нас генерує імпульси кроку |
| **PCNT** | Pulse Counter — апаратний лічильник імпульсів ESP32 |
| **FreeRTOS** | операційна система реального часу на ESP32 (задачі, пріоритети, таймери) |
| **ctypes** | спосіб викликати C-бібліотеку з Python |
| **RK4** | метод Рунге-Кутти 4-го порядку для чисельного інтегрування рівнянь руху |
