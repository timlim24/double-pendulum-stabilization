# Одинарний перевернутий маятник на візку (Single Inverted Pendulum)
## Гібридна система: Оптимальний підйом MPC (Swing-Up) + Стабілізація LQR

Ця директорія містить повноцінну автономну симуляцію одинарного маятника на рухомому візку з реалістичними параметрами фізичного стенду (Arduino / кроковий двигун / енкодер).

---

## 1. Чому маятник не піднімався при $A_{\max} = 15.0$, $V_{\max} = 0.66$, $L = 0.35$?

При переході від навчальної моделі ($L = 1.0$ м) до реалістичного фізичного макета виникають три критичні фактори:

### 1.1. Катастрофічний вплив тертя у шарнірі ($B_{\text{pend}}$)
* Момент інерції стержня відносно шарніра:
  $$I = \frac{4}{3} m l^2 = \frac{1}{3} m L^2$$
  При зменшенні довжини з $L = 1.0$ м до $L = 0.35$ м інерція зменшується у $(\frac{1.0}{0.35})^2 \approx 8.16$ разів ($I \approx 0.00408\text{ кг}\cdot\text{м}^2$ проти $0.0333\text{ кг}\cdot\text{м}^2$).
* Старе значення тертя $B_{\text{pend}} = 0.005\text{ Н}\cdot\text{м}\cdot\text{с/рад}$ для малого маятника створює критичне демпфування ($\zeta \approx 10\%$ втрат енергії за радіан), діючи як потужне гідравлічне гальмо.
* **Рішення:** Для реальних кулькопідшипників (608zz / вісь оптичного енкодера) коефіцієнт в'язкого тертя становить $B_{\text{pend}} \approx 0.0005 \dots 0.001\text{ Н}\cdot\text{м}\cdot\text{с/рад}$. У `config.py` встановлено $B_{\text{pend}} = 0.0008$.

### 1.2. Обрізання тяги при насиченні за швидкістю ($V_{\max} = 0.66\text{ м/с}$)
* При прискоренні $a = 15.0\text{ м/с}^2$ візок досягає максимальної швидкості $0.66\text{ м/с}$ всього за $t = \frac{0.66}{15} \approx 0.044\text{ секунди}$.
* Простий закон відсікання струму мотора (`if v >= v_max: u = 0`) вимикав силу на 80% часу півперіоду коливань, залишаючи візок котитися за інерцією без накачування енергії, тоді як центрувальна пружина сповільнювала його в неправильній фазі.

### 1.3. Зміна власної резонансної частоти
* Власна частота маятника:
  $$\omega_0 = \sqrt{\frac{3 g}{4 l}} = \sqrt{\frac{3 \cdot 9.81}{4 \cdot 0.175}} \approx 6.48\text{ рад/с}$$
  (період $T \approx 0.97\text{ с}$, що в 1.7 разів швидше за 1-метровий маятник). Попередній енергетичний коефіцієнт $k_e = 75$ призводив до надмірних ривків і насичення.

## 2. Як вирішує цю проблему MPC (Trajectory Optimization)

Замість емпіричного розгойдування нелінійний розв'язувач **CasADi + IPOPT** прораховує глобальну траєкторію розгону візка:
* Строго враховує обмеження $|v(t)| \le 0.66\text{ м/с}$;
* Строго враховує прискорення $|a(t)| \le 15.0\text{ м/с}^2$ ($|u(t)| \le 16.5\text{ Н}$);
* Утримує візок у межах $|x(t)| \le 0.14\text{ м}$ (при довжині рейки $\pm 0.5\text{ м}$ це лише 14 см розмаху!);
* Рівно за $3.6\text{ с}$ виводить маятник строго у вертикальне положення ($\theta = 0.00^\circ, \omega = 0.00\text{ рад/с}$), де керування плавно підхоплює LQR.

## 3. Структура модуля

```
single_pendulum/
├── config.py             # Фізичні параметри (M, m, L, a_max, v_max, b_pend)
├── lqr_controller.py     # Розрахунок матриці LQR через рівняння Ріккаті (scipy ARE)
├── mpc_generator.py      # CasADi + IPOPT оптимізатор траєкторії Swing-Up
├── mpc_controller.py     # Feedforward ZOH відтворювач траєкторії та Handover до LQR
├── mpc_trajectory.npz    # Попередньо розрахована оптимальна траєкторія
├── sim_pygame.py         # Інтерактивний 60 FPS Pygame симулятор
└── README.md             # Документація
```

---

## 4. Запуск

### Запуск симулятора:
```bash
./venv/bin/python single_pendulum/sim_pygame.py
```

### Перерахунок оптимальної траєкторії під інші параметри:
```bash
./venv/bin/python single_pendulum/mpc_generator.py
```

## 5. Керування в симуляторі

| Клавіша / Кнопка | Дія |
|---|---|
| **M** / `[▶ MPC Swing-Up]` | Запуск записаного оптимального підйому MPC |
| **E** / `[⚡ Енерго Swing]` | Альтернативний неперервний енергетичний підйом (Åström / Spong) |
| **A** / `[★ Авто LQR]` | Скидання слайдерів до аналітично оптимальних коефіцієнтів |
| **Space** / `[Мотор: УВІМК]` | Увімкнення / вимкнення мотора |
| **D** / `[⬇ Опустити вниз]` | Опускання маятника у висяче положення ($\theta = \pi$) |
| **R** / `[↻ Скинути]` | Скидання системи до початкового стану |
| **F11** / `[⛶ Екран]` | Повноекранний режим |
| **Мишка (ЛКМ)** | Фізичне перетягування вантажу або візка з урахуванням інерції |
